`/octopus:pr-ready` vira um pull request draft para pronto para
review. É a outra metade de [`pr-open --draft`](../pr-open/): um
comando abre o trabalho cedo, o outro declara que está pronto.

## Por que a promoção é um comando próprio

Pedir uma review e estar pronto para review são afirmações
diferentes, e o Octopus as mantém separadas. `pr-review` poderia
plausivelmente promover o PR em seu nome — você pediu uma review,
então presumivelmente está pronto — mas isso tornaria uma mudança de
estado voltada para fora um efeito colateral de um comando cujo
trabalho é ler um diff. Reviewers seriam notificados por algo que
você não pediu.

Então a promoção é explícita. `pr-open --draft` abre, você trabalha,
`pr-ready` declara, `pr-review` revisa.

## O número do PR é opcional

```bash
octopus pr-ready        # o PR aberto da branch atual
octopus pr-ready 238    # um PR explícito
```

Sem argumento, ele resolve o PR da branch em que você está, que é
como o comando é usado na prática — logo após o draft que você
acabou de abrir.

## A promoção é idempotente

Rodar em um PR que já está pronto imprime um aviso e termina com
sucesso. Não gera erro, e não chama o GitHub. Isso importa para
encadeamento: `dev-flow ready` em um fluxo pela metade, ou uma
segunda invocação depois que você esqueceu a primeira, nunca quebra
uma sequência.
