`launch-feature` pega uma feature que acabou de ser lançada e
produz os artefatos que o time precisa para anunciá-la. Ela cobre
dois públicos a partir de uma única fonte: superfícies de
**aquisição** (copy de landing page, posts sociais) e mensagens de
**lifecycle** para a sua lista de contatos existente (um email
HTML profissional e uma mensagem de WhatsApp), além de uma entrada
de changelog comercial e, opcionalmente, um roteiro de vídeo e
assets de imagem.

## Por que uma skill de lançamento em vez de "o marketer escreve"

Dois motivos:

- **O contexto da feature é local.** A copy de lançamento que
  funciona bem se refere ao problema real que a feature resolve
  — a motivação do RM, as restrições da spec, o diff do PR. Esse
  contexto vive no repo, não na cabeça do marketer. Gerar a
  partir da fonte faz com que o lançamento combine com a feature.
- **O lançamento é multi-canal.** Email, WhatsApp, X, LinkedIn,
  Instagram, landing page — cada um tem uma voz e um comprimento
  diferentes. Escrever cada versão manualmente é trabalhoso e
  propenso a divergência entre canais. A skill produz todas a
  partir de uma única fonte, aplicando a voz específica de cada
  canal, e você pode restringir a um subconjunto — por exemplo
  `--channels=email,whatsapp` para um anúncio de lifecycle à sua
  lista.

## O que entra em um kit de lançamento

A saída fica em
`docs/marketing/launches/YYYY-MM-DD-<slug>/`:

| Arquivo | Canal |
|---|---|
| `copy-lp.md` | Copy da seção de landing page |
| `email.md` | Email de anúncio — copy |
| `email.html` | Email de anúncio — HTML pronto para envio (tokens de marca, rodapé com unsubscribe, links com UTM) |
| `whatsapp.md` | Mensagem de broadcast no WhatsApp |
| `post-instagram.md` | Post no Instagram |
| `post-linkedin.md` | Post no LinkedIn |
| `thread-x.md` | Thread no X / Twitter |
| `changelog-vendedor.md` | Entrada de changelog comercial (voltada ao usuário) |
| `roteiro-video.md` | Roteiro de vídeo de 60-90 segundos (se aplicável) |
| `image-prompts.md` / `images/` | Assets de imagem opcionais |
| `README.md` | Índice do kit, registrando qual fonte de override cada canal usou |

O time escolhe quais canais são relevantes e ignora os demais —
a skill produz todos para eliminar a fricção do "eu também
deveria escrever uma mensagem de WhatsApp".

## Voz por canal

- **Email** — segunda pessoa, focado em benefício, estruturado
  como *o que mudou / por que importa / o que fazer*, com uma
  única chamada para ação. A variante HTML carrega os tokens de
  marca de `brand.yml`, um rodapé com unsubscribe + endereço da
  empresa e links com UTM; a copy segue o framework de email SaaS
  embutido.
- **WhatsApp** — curto: um headline em negrito, uma linha de
  gancho, até dois destaques e um link de CTA.
- **X** — thread; o primeiro post é o gancho, os seguintes
  desenvolvem o caso de uso, o último post é o link.
- **LinkedIn** — mais longo que o X, tom profissional, post único.
- **Instagram** — legenda visual-first com gancho e CTA.
- **Copy de landing page** — terceira pessoa, headline focada em
  benefício, pontos técnicos de prova.
- **Changelog comercial** — tom neutro, focado no comportamento
  visível ao usuário, sem jargão interno.

## Aprovação obrigatória por design

A skill rascunha; ela não publica. Todo artefato é entregue como
um arquivo que o time revisa antes de enviar. A allowlist `tools:`
do role marketer explicitamente proíbe as ferramentas de
modificação de arquivos ou de rede que permitiriam a um agent
publicar de forma autônoma — uma proteção deliberada.

## Combinando com `launch-release`

`launch-feature` anuncia uma feature lançada. `launch-release`
anuncia uma release inteira que agrupou várias — ela adiciona um
resumo de release notes, uma entrada de status page, um banner
in-app e uma landing page temática, canais que cabem em uma
release versionada, mas não em uma feature isolada.
